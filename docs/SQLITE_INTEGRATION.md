# ClimateIQ v5 — SQLite Integration Guide
## Final Year Project Documentation Supplement

---

## Overview

ClimateIQ v5 replaces manual CSV browsing with an **embedded SQLite database**
(`database/climate_data.db`). The database is pre-processed once from your CSV
and then queried directly at runtime — no file dialogs, no full-file loads.

## Quick Start

### Step 1 — Install dependencies

```bash
pip install -r requirements.txt
```

### Step 2 — Convert your CSV to SQLite (run once)

```bash
python scripts/csv_to_sqlite.py path/to/your_climate_data.csv
```

The script auto-detects column aliases (same flexible matching as v4) and
writes `database/climate_data.db`.

To overwrite an existing database:

```bash
python scripts/csv_to_sqlite.py path/to/data.csv --replace
```

### Step 3 — Run the application

```bash
python main.py
```

The application connects to the database automatically on startup.

## Database Schema

```sql
CREATE TABLE climate_tweets (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    text        TEXT,           -- tweet / post text
    sentiment   TEXT,           -- 'positive' | 'negative' | 'neutral'
    score       REAL,           -- VADER compound score (-1.0 to 1.0)
    emotion     TEXT,           -- joy | anger | fear | sadness | ...
    topic       TEXT,           -- temperature | flooding | drought | ...
    city        TEXT,           -- city / region name
    tweet_date  TEXT,           -- ISO-8601 date: 'YYYY-MM-DD'
    weather     TEXT            -- weather condition
);

-- Indexes for fast filtering
CREATE INDEX idx_city      ON climate_tweets(city);
CREATE INDEX idx_date      ON climate_tweets(tweet_date);
CREATE INDEX idx_sentiment ON climate_tweets(sentiment);
CREATE INDEX idx_city_date ON climate_tweets(city, tweet_date);  -- composite
```

## Efficient SQL Query Examples

### All records for a city in a date range
```sql
SELECT text, sentiment, score, emotion, topic, city, tweet_date, weather
FROM   climate_tweets
WHERE  tweet_date BETWEEN '2023-01-01' AND '2023-12-31'
  AND  LOWER(city) = LOWER('Karachi')
ORDER  BY tweet_date
LIMIT  50000;
```

### Sentiment distribution for a city
```sql
SELECT sentiment, COUNT(*) AS count
FROM   climate_tweets
WHERE  city = 'Lahore'
GROUP  BY sentiment
ORDER  BY count DESC;
```

### Top 10 cities by tweet volume
```sql
SELECT city, COUNT(*) AS tweets
FROM   climate_tweets
GROUP  BY city
ORDER  BY tweets DESC
LIMIT  10;
```

### Average VADER score by month (trend analysis)
```sql
SELECT SUBSTR(tweet_date, 1, 7) AS month,
       ROUND(AVG(score), 4)     AS avg_score,
       COUNT(*)                 AS records
FROM   climate_tweets
WHERE  city = 'Islamabad'
GROUP  BY month
ORDER  BY month;
```

### Emotion breakdown with percentages
```sql
SELECT emotion,
       COUNT(*)                                    AS count,
       ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER(), 1) AS pct
FROM   climate_tweets
WHERE  tweet_date BETWEEN '2023-01-01' AND '2023-06-30'
GROUP  BY emotion
ORDER  BY count DESC;
```

### Date range available in the database
```sql
SELECT MIN(tweet_date) AS earliest,
       MAX(tweet_date) AS latest,
       COUNT(*)         AS total_records
FROM   climate_tweets;
```

## Changes from v4 to v5

| Area | v4 (CSV) | v5 (SQLite) |
|------|----------|-------------|
| Data loading | `pd.read_csv()` on user-selected file | Auto-connect to embedded DB on startup |
| UI | "Browse CSV File" button | Removed; status label shows DB connection |
| Data class | `DataManager` in `core/data_manager.py` | `DatabaseManager` in `core/db_manager.py` |
| Import alias | `from core.data_manager import data_manager` | `from core.db_manager import db_manager as data_manager` |
| Memory | Entire CSV loaded into RAM | Only queried rows loaded per analysis |
| Filtering | Pandas boolean masks on full DataFrame | SQL `WHERE` + `LIMIT` at query time |
| Startup time | Slow (full CSV parse) | Fast (DB connection only) |
| chart_engine | Unchanged | Unchanged |
| pdf_reporter | Unchanged | Unchanged |
| ai_explainer | Unchanged | Unchanged |

The `compute_stats()` signature and return dict are **identical** between v4 and v5,
so `chart_engine.py`, `pdf_reporter.py`, and `ai_explainer.py` required zero changes.

## Performance Optimisations

1. **Composite index** on `(city, tweet_date)` — the most common query pattern.
2. **WAL journal mode** — enables concurrent reads without locking.
3. **ISO-8601 text dates** — `BETWEEN` on text works correctly and avoids
   expensive date-parsing functions in SQL.
4. **LIMIT clause** — `filter_data()` defaults to 50,000 rows, preventing
   runaway queries on very large databases.
5. **Connection-per-query** pattern — uses Python's `with sqlite3.connect()`
   context manager; no persistent connection needed for a desktop app.
6. **`pd.read_sql_query()`** — pulls query results directly into a DataFrame
   in one network round-trip, avoiding intermediate list conversions.

## Embedding the Database in the Application

The database lives at `database/climate_data.db`, resolved relative to the
project root using `pathlib.Path(__file__).resolve().parent.parent`.
This means the path works correctly regardless of the working directory from
which `python main.py` is invoked, and survives being packaged with PyInstaller:

```python
# In db_manager.py
_HERE   = Path(__file__).resolve().parent   # core/
_ROOT   = _HERE.parent                       # project root
DB_PATH = _ROOT / "database" / "climate_data.db"
```

For PyInstaller packaging, add to your `.spec` file:

```python
datas=[('database/climate_data.db', 'database')],
```

## FYP Documentation Notes

- The SQLite integration demonstrates knowledge of **relational database design**,
  **SQL query optimisation** (indexes, composite keys, parameterised queries), and
  **software architecture** (separation of data layer from UI).
- The `csv_to_sqlite.py` conversion script demonstrates an **ETL pipeline**
  (Extract → Transform → Load) with data validation and normalisation.
- The use of `sqlite3` (Python standard library) keeps the project lightweight
  and avoids external database server dependencies — ideal for a portable FYP demo.
